## 目的と役割

- Studio: 現在の構成を編集し、画像を生成する。
- Library: 生成済み画像を探し、閲覧・再利用する。
- 第3項目 Scenes（名称は仮）: キャラクターを入れ替えて使える場面を保存・整理し、次の制作へ適用する。

## 適用ルールの具体例

| 場面の保存内容 | Studioへの適用結果 |
| --- | --- |
| 背景を保存対象にし、内容が「夜の街」 | 現在の背景を「夜の街」に置き換える。対象外の衣装などは維持。 |
| 背景が対象外、または対象でも空欄 | 現在の背景を維持。 |
| LoRAが対象外、または保存0件 | キャラクターを含む現在のLoRA構成を維持。 |
| 画風LoRA Aをweight 0.6で保存し、利用可能 | 現在のキャラクターLoRAを維持し、それ以外をA 0.6の構成へ置き換える。 |
| Negativeが対象で空でない | 手入力Negativeを置き換える。対象外・空欄なら維持。 |
| 保存元Checkpointと現在のCheckpointが異なる | 現在のCheckpoint・生成設定・画像サイズを維持。保存元名は参考表示。 |
| 場面がNSFW、Studioが一般 | 適用時にStudioの生成分類もNSFWへ変更。 |

## 初回実装の範囲

- Scenesへのnavigation、カード一覧、名前検索、一般／NSFW filter、更新順、Studio往復時の一覧状態保持。
- Libraryからの新規保存、保存項目とLoRAの選択、任意Negative、名前・分類・代表画像・保存元Checkpoint情報。
- Raw／旧履歴からの手動編集保存。
- Scenesでの編集、上書き保存、別名保存、削除、Library画像への代表画像変更。
- 場面選択からの適用・Studio移動、不足LoRA表示と残りを適用する選択。
- 同一LICへ接続する端末間の共有、元画像削除に依存しない場面・代表画像の保持。

初回には、Studioからの新規保存、適用取消、画像アップロード、追加のCheckpoint filter・タグ・folder、キャラクター自動推測を含めない。正式名称・配置・視覚デザインは別途設計する。

## 確認済み要件に基づく完了条件

以下は今後の実装を検証する条件であり、現時点での実施結果ではない。

1. Libraryから選択した項目で場面を保存し、別端末のScenesで同じ場面を閲覧・使用できる。
2. カードに代表画像・名前・保存元Checkpointが表示され、名前検索・分類filter・更新順・往復時の状態保持が動作する。
3. 場面適用でキャラクター、対象外項目、空欄、LoRA保存0件、現在Checkpointと生成設定・画像サイズを維持する。
4. 対象の空でないPrompt／Negative、1件以上のLoRA構成とweightを反映し、生成分類を場面へ合わせ、Studioへ移動する。
5. 不足LoRAの名前が分かり、残りだけ適用するか選べる。
6. Raw／旧履歴でも元Promptを見ながら手動編集して保存できる。
7. 名前・内容・代表画像の変更、上書き保存・別名保存・削除が動作する。
8. Library元画像を削除した後も場面と代表画像を閲覧・使用できる。
9. PCと390〜430pxの画面で保存・検索・選択・編集を操作できる。実機Safari等の検証条件は実装計画で明示する。

## 技術的な整理と提案（独立したユーザー承認ではない）

- 保存対象外と空値は、適用時にはいずれも現在値維持。空白だけの入力等の正規化は設計で定義する。
- Libraryの生成記録とScenesの編集可能な保存内容を独立させ、場面の編集で過去の生成記録を書き換えない。
- 既存の部分プロファイルはPromptへ適用中のsnapshotを持つ。場面の置き換え時に旧profileの内容が残らないよう、対象sectionの本文とprofileの扱いを設計する必要がある。
- Checkpointから派生する管理タグを、保存元の画風や手入力Negativeとして誤って固定しない。古い履歴で手入力と自動分を区別できない場合の扱いは未確定。
- Studioへ移動した時点では生成を開始しない想定。選択は編集構成への適用とし、通常の生成操作につなぐ。
- 実装方式、API、保存schema、既存Checkpoint Setとの連携は未決定。
- S18は成功した適用を手動で取り消す機能の除外であり、適用失敗時に半端な構成を残してよいことを意味しない。失敗時の整合性維持は設計で扱う。
- 不足LoRAの適用を断った場合は、生成分類を含むStudioの現在構成を変更しない設計を推奨する。

## 技術設計で詰める事項

以下は[Scenes設計書](scenes-design.md)で対処案を記載済み。実装済み・追加操作の本人承認済みを意味しない。

- 正式名称。
- LoRAのキャラクター判定と例外、適用中section profileとの関係。
- 保存LoRAは1件以上だが全件不足して結果的に0件になる場合の扱い。既存LoRAを維持する方向を推奨するが、保存0件と利用可能0件を混同せず適用結果を明示する。
- StudioがRaw編集中の場合の適用方法。S20は保存元履歴の扱いであり、現在のRawからキャラクターを自動分離できるという約束ではない。
- 生成中の適用、適用失敗時の復元、複数端末からの同時編集。
- 元履歴に保存元Checkpoint情報がない場合は不明として扱い、現在値等で捏造しない。
- 既存保存機能との関係、保存形式と代表画像の独立保持方式、画面設計。
